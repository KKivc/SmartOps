## 4. 端到端对话测试（3/3）

### 测试 1：查询服务器列表

**输入：** 「有哪些服务器？」

**流程：**
```
用户 → POST /api/chat
  → agent.py 保存消息 → build_supervisor().invoke()
    → supervisor_node: LLM 决策 → infra_worker
    → infra_worker_agent: 调用 get_server_list（新增）
    → 返回 Supervisor → FINISH → finish_node → RCA 报告
  → 保存 AI 回复 → 返回
```

**输出：** 服务器表格（名称/IP/状态/操作系统）+ 在线/离线统计

**验证：** ✅ 消息存入 `messages` 表，`conversations` 表摘要更新

### 测试 2：日志分析

**输入：** 「web-01 最近有没有报错日志？」

**流程：**
```
→ supervisor_node: LLM 决策 → log_worker
→ log_worker_agent: 调用 count_by_level（1h → 24h → 7d）
→ 返回 Supervisor（数据为空）→ FINISH → finish_node
→ LLM 生成完整 RCA 报告
```

**输出：** ⭐ 结构化 RCA 报告
- 概要：web-01 最近 7 天无日志
- 时间线：1h → 24h → 7d 逐步扩展
- 根因分析：3 种可能性（名称不匹配/未接入/标签结构不符）
- 证据：Log Worker 原始数据表
- 修复建议：4 条可操作步骤（含命令）
- 预防措施：3 条长期建议

**验证：** ✅ RCA 格式完整，Markdown 结构正确，结论基于数据

### 测试 3：简单对话

**输入：** 「你好，请简单介绍一下你自己」

**流程：** Supervisor → FINISH（无需 Worker）→ LLM 直接回答

**输出：** 「您好，我是 SmartOps 运维助手，有什么可以帮助您的？」

**验证：** ✅ 非故障场景正确降级

## 5. 修复摘要

本轮修复的 4 个 prompt 问题：

| # | 问题 | 修复 | 影响 |
|---|------|------|------|
| 1 | Infra Worker 没有服务器名→IP 映射 | 新增 `get_server_list` 工具 + prompt 更新 | 端到端测试通过 |
| 2 | Prompt 中 PromQL 示例与 `query_metric` 接口不一致 | 改为裸指标名 + 说明 | EDD 验证通过 |
| 3 | Worker 收到用户原始问题而非精确指令 | Supervisor 输出 `sub_question` 字段 | EDD 验证通过 |
| 4 | JSON 中嵌入多行 Markdown 导致解析失败 | Supervisor 只输出路由，RCA 移入 `finish_node` | EDD 验证通过 |
